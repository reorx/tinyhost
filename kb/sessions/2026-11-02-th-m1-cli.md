## 实现说明

新增 `internal/cli` 和 `cmd/tinyhost`。采用 stdlib flag 和 `register(&command{...})` 分发，支持位置参数和选项交错、全局选项放在命令前后，以及 `data --json push ...`。包含 deploy、data push/rm、apps、info、versions、promote、delete、whoami、version、help、skill。无参数运行时帮助第一行为 brief 指定的 Agent 指令。

远端命令只序列化 `internal/api` DTO；本地命令新增 VersionResult、HelpResult、SkillResult，未修改任何已冻结的 HTTP 字段。`docs/json-output.md` 补齐每个命令的输出类型、错误流、退出码、本地错误 code、配置优先级及写回失败语义。

服务器读取顺序为 --server > TINYHOST_SERVER > 平台配置目录 tinyhost/config.json；只有高优先级缺失时才读文件，不让无关损坏配置阻塞显式地址。服务器地址只接受 http(s) origin。M1 token 来源仅 TINYHOST_TOKEN；缺失/无效 token 退出 3。HTTP 设置两分钟超时，拒绝自动跟随重定向，代理的非 JSON 错误会显示 HTTP 状态。

deploy 使用已有 bundle.Pack，成功/失败都清理临时压缩包。只有 --create 成功后才将 app 写回目录的 tinyhost.json，单 HTML 文件则写到所在目录。manifest 用 map[string]any 和 UseNumber 读取，只设置 app，按两空格缩进输出，保留未知字段、大整数及其他元数据；显式 --title 优先于 manifest，更新时不改变可见性。写回失败时远端发布已完成，因此输出成功结果并在 stderr 告警，专门行为测试使用只读 manifest 验证。

可读输出包含创建者、时间、数据声明和覆盖目录来源；no-promote 说明主入口仍指向的版本，删除提示恢复期限。所有符号链接跳过警告进入 stderr，不污染 JSON。
