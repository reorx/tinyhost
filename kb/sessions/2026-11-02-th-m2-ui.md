## 设计上的主要决定

**整体取向。** 这是 Operate 类界面：一个人用、任务导向，桌面浏览为主，手机上只做批准和登录。视觉上克制：暖白纸色底（`#f6f5f1`）、近黑文字、一个绿色强调色（`#1f7a4d`，深色下 `#4cc38a`）只用于主操作、当前态和「公开」标记；危险操作统一用红色描边按钮，警示信息（待批准申请、登录防钓鱼提示）用琥珀色。字体全用系统字体栈，slug、版本号、验证码、目录、IP、token 这类数据用等宽字体。浅色和深色的令牌都在 `:root` 定义，深色走 `prefers-color-scheme`，并声明 `color-scheme: light dark` 让原生控件跟随。

**手机优先的两页。**

- 登录页：防钓鱼提示放在密码框之前，琥珀色底、盾牌图标，`{{.AdminURL}}` 加粗等宽单独成行，并补一句「输入前先看一眼地址栏。在 App 页面里出现的密码框都不是 tinyhost 的」。密码框和按钮高 50px，输入框字号 16px，避免 iOS 聚焦时缩放。
- 批准页：验证码放大到 32px 等宽、加连字符显示，旁边写「N 分钟后过期」，提示 Owner 先核对验证码。设备信息拆成 名称 / 主机名 / 系统与架构 / CLI 版本 / 来源 IP / 申请时间 六行。有效期用三段式选择（44px 高）。「批准」是满宽绿色主按钮；「拒绝」在虚线分隔、36px 间距之后，前面有一句「不认识这个申请，或者验证码对不上？」，红色描边，两者不会误点。结果页分别处理已批准（回显名称和有效期）、已拒绝、已过期、已处理、验证码不存在；后三种状态下方提供手动输入验证码的表单（GET `/device?code=`，复用现有路由）。

**其余页面。**

- 顶栏：品牌 + 四个导航 + 「Owner」账户菜单（原生 `<details>`）。「退出」和「退出所有会话」都在菜单里，后者红色、带说明「所有浏览器都要重新登录，手机丢了时用」，继续用 `data-confirm`。手机上导航换到第二行，可横向滚动。
- 首页：待批准申请只在有数据时出现，放在最上方的琥珀色区块，每行整行可点。App 列表 + 右侧「新建 App」面板（≤960px 时面板落到列表下方）。
- App 详情：标题区（slug、标题、「打开主入口」）→ 摘要（主入口链接 + 复制、可见性、当前版本、创建者、时间）→ 版本表 → 覆盖目录与声明的数据目录并排 → 设置（可见性、改 slug）→ 最近操作 → 单独的「危险操作」区放删除 App。版本删除、撤掉覆盖目录、删除 App 都是红色描边并保留 `data-confirm`，确认文案里带上版本号或目录名。
- 回收站：剩余 ≤1 天时标签变琥珀色。Agent：状态用颜色区分，撤销或过期的行变灰；签发 token 后在页顶用绿色区块显示一次，带复制按钮和「只显示这一次」。
- 操作记录：筛选从「输入 App ID + datalist」改成下拉选择 App；筛选值不在活跃 App 里（回收站或已清理）时自动补一个「（已删除）」选项，所以审计行里的链接仍然可用。表格时间用「11-02 17:35」格式，悬停显示完整时间。

**表格在窄屏下的处理。** ≤720px 时所有 `.tbl` 改成堆叠行：`primary` 单元格占满第一行，其余单元格作为一行元信息自动换行，`data-label` 在手机上显示为前缀（如「到期 30 天后」），`.full` 单元格（说明、操作、摘要）各占一行。不用横向滚动容器，也不会撑破页面。

**admin.js 的职责**（仍无内联脚本）：`data-confirm` 确认；把 `<time data-ts>` 渲染成本地时间（默认相对时间，`data-format="datetime"` / `"short"` 为绝对时间），每 30 秒刷新一次；`data-copy` 复制按钮（剪贴板不可用时保持 `hidden`）；账户菜单点外面或按 Esc 关闭。

**没有采用的做法。** impeccable skill 默认要先写 PRODUCT.md / DESIGN.md，任务限定只改 `views/`，所以没写，设计决定都记在本节。时间格式化没有用服务端模板函数：模板函数要改 `adminTemplates` 的构造，超出「只加 view model 字段」的范围；另外服务器多半跑在 UTC，浏览器本地时区反而更符合 Owner 的需要。

## 接口与测试

### view model 增量

| 位置 | 增加 | 填值 |
|---|---|---|
| `admin.go` `DeviceView` | `Info DeviceInfo`：Hostname、OS、Arch、CLIVersion、RequestIP | `devicePage`：有 Request 时 `json.Unmarshal(d.Meta)`，解析失败只留空 |
| `admin.go` `DeviceView` | `Name, TTL string` | `deviceDecision`：status 为 approved 时填批准名称和 ttl 表单值；拒绝时为空 |

原有字段、路由、表单 action 和字段名都没变。新增的表单字段只有登录页隐藏的 `username`（值固定 `owner`，服务端不读）。可见性、有效期从 `<select>` 改成同名的 radio 组，字段名和取值不变。

### 测试

- 新增 `TestDevicePageShowsRequestFactsAndApprovalResult`（`internal/server/auth_test.go`）：批准页分别显示验证码、主机名、`linux/arm64`、CLI 版本、来源 IP；批准结果回显名称和「永久」。先把旧 `device.html` 放回去跑，确认失败，再换回新模板通过。
- 没有调整任何已有断言。模板里有两处依赖，改界面时要注意：
  - `TestEventsRecordedForOwnerAndAgentActions` 用 `strings.Cut(page, "<table>")` 切出审计表，再断言表里没有其他 App 的 slug。所以操作记录页的审计表必须是第一个、并且不带属性的 `<table>`（样式挂在外层 `div.tbl` 上），App 筛选下拉必须放在表格之前。
  - 同一测试断言页面包含 `owner`：审计表把原始 actor 放在操作者的 `title` 属性里（Agent 行是 client ID，悬停可区分同名 Agent），并且动作列同时输出原始动作码。

## 交给协调者

- 后端：`internal/store/versions.go:147` 总是传 `&manifest.Title`（非 nil），`COALESCE` 不生效。App 包里没有 `tinyhost.json` 的 title、也没传 `--title` 时，再次 deploy 会把已有标题清空。复现：演示数据里 `home-moodboard` 首次 deploy 带 `--title`，第二次不带，标题变成空字符串。
- 表单失败仍是纯文本错误页（`consoleError` 的 400/404/409、登录 429、`deviceDecision` 的 400）。要做成带样式、带返回链接的错误页，需要加一个错误模板并改 handler 的输出方式，建议放进 M3 UI 任务。
- spec 写「每个版本都有'打开'和'设为主入口'」。我对当前主入口版本隐藏了「设为主入口」（对它操作没有效果），改为显示「主入口」标签。如需严格按 spec，在 `app.html` 版本行去掉 `{{if not .Current}}` 对该表单的包裹即可。
- `th-m2-accept` 可以直接复用 `demo.py` 造数据：`setup` 之后起服务，再跑 `seed` 和 `pending`。
- 没做的：没有真实手机、Safari、Firefox 验证；无 JS 时时间显示为 Unix 秒。
