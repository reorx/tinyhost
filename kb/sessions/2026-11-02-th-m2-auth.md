## 实现说明

### 存储与安全边界

`internal/store/auth_schema.sql` 是 user_version=2 迁移，从真实 M1 数据库升级并重开两次有测试，原 clients 行保留。新增 settings、device_requests、sessions、view_tickets、slug_redirects，保留 M1 全部表及 DTO。GC 清理过期一天的申请、过期会话和票据。

设备批准只修改申请；PollDevice 在一个 SQL 事务里校验状态、轮询间隔、创建 client（保存 metadata）、消费申请。并发八个轮询只会创建一个 client。token、设备码、cookie ID、票据只存 SHA-256。验证码使用规定字母表，输入去空格/连字符并转大写。

新增 `SlugOwner` 供创建时检查当前 slug 和历史 redirect；CreateApp 在数据库层用触发器拒绝占用 redirect。没有实现改名或重定向 HTTP 行为，留给 console；AppBySlug 继续只查询当前路径。

Agent API 所有受控写操作保持 Bearer-only；设备码和轮询端点是无凭证的协议入口。viewer cookie 仅在内容托管时读取，不能鉴权管理操作。所有 401 hint 为「运行 tinyhost login 重新授权」。私有内容在文件/版本查询之前检查 viewer 会话，主入口和版本的成功响应均为 `private, no-cache`。页面导航跳转 admin，非导航返回 401。

票据有效 60 秒，绑定 next_path，原子单次消费；admin/viewer 会话固定 30 天、不续期。next 校验同时拒绝非站内路径、双斜杠、反斜杠、控制字符。退出只删除当前 admin 会话；logout-all 清空全部 admin/viewer 会话。

### admin 骨架

`Server.Handler()` 创建 Agent mux 和 `s.adminHandler()`，按配置的 Host 分流；admin 不经过 Agent mux。console 在 `internal/server/admin.go` 的 `adminHandler` 内注册新 handler，即自动继承 `adminMiddleware`。

中间件顺序：统一 CSP/COOP/Referrer-Policy/no-store → 每个 POST 校验 Origin（缺失时仅接受 Sec-Fetch-Site: same-origin）→ 查询 owner_password_hash（未设置则所有页面显示设置提示）→ 除 login/static 外校验 kind=admin 会话 → mux。未登录 GET/HEAD 跳 `/login?next=<原路径与查询>`，写请求返回 401。未知 admin 路由同样受到中间件保护。

路由和表单契约：

| 路由 | 字段 / 行为 |
|---|---|
| GET /login | query next；显示密码表单 |
| POST /login | password、next；bcrypt cost 12 验证，种 admin cookie，302 返回安全 next |
| POST /logout | 无字段；删除当前会话并清 cookie |
| POST /logout-all | 无字段；清所有会话并清 cookie |
| GET / | 受保护的占位首页；console 替换此 handler |
| GET /device | query code；显示申请元数据、状态和表单 |
| POST /device/{id}/approve | name；ttl 为 1d / 30d（默认）/ forever |
| POST /device/{id}/deny | 无字段 |
| GET /view-auth | query next；生成票据，302 到 apps /_/auth |
| GET /static/* | embed 静态资源；已有无内联代码的 admin.js 占位 |

apps `GET /_/auth` 使用 query ticket、next，兑换 viewer cookie 并 302 到原路径。正常使用 `__Host-th_admin` / `__Host-th_view`，HttpOnly、Secure、Lax、Path=/、无 Domain。insecure 模式为 th_admin / th_view，去 Secure 和前缀；serve 打印开发警告。

模板由 `viewFiles embed.FS` 嵌入 `views/*.html` 和 `views/static/*`，`adminTemplates` 一次 ParseFS，`s.render(w, "文件名.html", 具名模型)` 渲染。模板无样式、无内联脚本，遵守 CSP；界面任务可直接改该目录。view model：

| 模型 | 字段 |
|---|---|
| LoginView | Next、Error、AdminURL string |
| DeviceView | Request *store.DeviceRequest；Message string |
| HomeView | Message string |

Request 可用字段：ID、UserCode、Name、Meta（JSON 字符串，含 hostname/os/arch/cli_version/request_ip）、Status、ApprovedName、TokenTTL、ClientID、CreatedAt、ExpiresAt、LastPolledAt；DeviceCodeHash 是服务端内部字段，模板不得输出。当前模板用 dl 展示申请信息。批准成功后 Request=nil、Message=approved；拒绝时为 denied；已处理/过期/不存在显示 Message。

console 添加页面：在 views/ 新建 html，定义具名 view model，在 adminHandler 注册 GET/POST；调用 Store 方法执行操作，审计使用现有 AddEvent + OnEvent 约定。现有 `ownerEvent(action, detail)` 记录 owner 审计；涉及 App 的事件需给它增加 app ID 参数或另加对应 helper，避免事件丢失 App 关联。路由、现有字段和模型字段只增不改。

### CLI 与命令入口

`tinyhost-server passwd [--data-dir DIR]`：终端用 x/term 无回显读两次；管道读一行；bcrypt cost 12；拒绝空密码；改密码清浏览器会话。serve 现在要求 admin-url，且 host 与 apps 不同。

CLI token 优先级为环境变量 > credentials.json 的 server 条目。login 默认 username@hostname，可 force 重新申请；有效凭证先 whoami 验证；pending 文件存服务器、秘密设备码、用户验证码、批准链接、过期时间和可选 interval。等待退出 4 后继续同一申请；slow_down 将间隔加 5 秒；拒绝/过期清申请；logout 撤销 token 并移除本地该服务器条目。已撤销的 token 也能退出；网络失败保留本地凭证方便重试。whoami 文本增加永久/到期时间，JSON 字段不变。

新增四份 golden：login_pending、login、login_env、logout；更新 help、skill、missing_token、unauthorized 四份以反映授权流程。skill 包嵌入 `skill/SKILL.md`，CLI skill 直接输出，本期正文只有登录一节，M3 可扩展并供 HTTP 复用。
