## 设计上的主要决定

沿用 M2 的设计语言（暖白纸色底、近黑文字、绿色强调色只给主操作、琥珀色表示警示、红色描边表示危险操作、数据用等宽字体、令牌放在 `:root`），没有另起一套。新增的样式都是新类名，追加在 `admin.css` 的「error page」「previews」「apps origin」三节和响应式段里。

**后台预览页。**

- 列和 M2 的列表页对齐：来源与链接 / Agent / 最近更新 / 状态 / 操作。页头和回收站一样，标题在左，说明在右：「拿到链接的人不用登录就能打开。到期后显示「已过期」，再过 7 天彻底删除。」
- 主单元格三行：来源目录名（等宽加粗；`Source` 为空时显示灰色的「未记录来源目录」）、预览链接（新标签打开，`rel="noopener noreferrer"`，因为目标是不可信内容）、预览 ID（小号灰色，`tinyhost previews rm` 用得上；手机上隐藏）。
- 状态列用徽标加相对时间：有效是绿色「有效 · 23 小时后到期」，过期是灰色「已过期 · 3 小时前」，过期行的来源和链接整体变灰。
- 操作：有效的预览有「打开」「复制链接」「删除」三个按钮；过期的只剩「删除」，打开或复制一个只会返回 410 的链接没有意义。删除继续走 `data-confirm`，确认文案按状态区分：「链接会立即失效，打开的人会看到 404」和「它已过期，删除后链接直接变成 404」。
- 空态：「还没有预览。」以及 `tinyhost preview <目录>` 的提示。

**后台错误页。**

- 用 solo 单栏布局（和登录页、批准页一样），不放后台导航。原因：401、403、429 出现时不一定有会话，导航里的退出表单在这种时候没有意义；`ErrorView` 也没有会话状态。
- 层级：图标 → `404 找不到` 眉标（等宽状态码加中文分类）→ 标题用 `Description`（服务端给的具体原因，如「App 不存在或已删除」「slug 已被占用」「登录过于频繁」）→ 一句按状态码写的处理建议。没把英文 `Title` 放进页面，tab 标题用「404 找不到 · tinyhost」。
- 颜色：404 中性，5xx 红色，其余琥珀色。图标：401 锁，403 盾牌，404 放大镜，429 时钟，其他是警告三角。
- 429 的建议是「为了防止密码被猜测，登录尝试有次数限制。等一分钟再试。」，依据是 `allowRate` 每 IP 每分钟 5 次的令牌桶。
- 两个出口，满宽 50px 高，在手机上好按：主按钮指向 `BackURL`（401 时文字是「去登录」，其余是「返回后台首页」）；次按钮「返回上一页」由 `admin.js` 的 `data-back` 控制，只在 `history.length > 1` 时出现。CSP 禁止 `javascript:` 链接，所以没法用内联方式。

**apps 根路径说明页。**

- 读者首先是 Agent（可能 curl 下来当文本读），其次是误入根路径的人。所以 HTML 的阅读顺序就是说明顺序：标题「这是一个 tinyhost 服务」→ 一句话说明（附 `<AppsURL>/<slug>/` 的路径示例）→「Agent 从这里开始」三步有序列表 → 防钓鱼提示 → 页脚的服务器地址和版本。head 里加了 `<link rel="alternate" type="text/markdown" href="/skill.md">` 和 meta description，方便 Agent 发现。
- 三步：① 安装 CLI（命令框带绿色描边光晕，复制按钮是主按钮，下面说明装到哪、会写服务器地址、再运行就是升级）；② `tinyhost skill`（附 `/skill.md` 链接，「没装 CLI 也能先读，内容相同」）；③ `tinyhost login`，把链接原样发给用户等批准。spec 只要求前两步，第三步是我加的。根页是 Agent 的第一个落点，有了它，只读这一页的 Agent 也知道完整路径；文字和 skill 一致。
- 命令前的 `$ ` 用 CSS `::before` 画，选中复制时不会带上；复制按钮复用 `admin.js` 的 `data-copy`。
- 防钓鱼：页面没有任何表单和输入框（新测试会检查），底部用中性 callout 写明「这个域名上的页面不会向你要 tinyhost 的密码。哪个页面要你输入 tinyhost 的密码，哪个就是假的。」。和登录页那句「tinyhost 只会在 admin 地址要求输入密码」呼应，但不在公开页面上写出 admin 地址。
- 手机上步骤不再缩进（序号放在标题旁边，去掉连接线），命令框占满宽度。这样生产地址 `https://th.reorx.com/install.sh` 能整段放在一行，不会从 URL 中间断开。

**预览过期页。**

- 单栏、居中、琥珀色时钟图标，标题「这个预览已过期」。正文写明到期时间（`<time data-format="datetime">`，按访问者的本地时区显示），然后告诉访问者「请联系发给你链接的人，请对方重新生成预览」。
- 读代码确认过一个细节，写进了文案：过期后的 7 天墓碑期内，同一个 Agent 在原目录再运行 `tinyhost preview`（不加 `--new`）会复活同一个 token（`CommitPreview` 按 client + local_key 更新原行）。所以正文写「通常链接不会变，对方生成后刷新这个页面就行」，页脚给 Agent 写了一句准确的操作说明。
- 资源用绝对路径 `/_/static/…`，在 `/_p/<token>/任意深度/` 下都能加载（CDP 检查覆盖了 `/_p/<token>/a/b/c/page.html`）。品牌用不带「后台」字样的 `site-brand`，指向 apps 根页。

**没有采用的做法。** 根页没有另建 `site.css`：apps 域名的两页共用 `admin.css` 的令牌和组件，CSS 只有一份，而且 `/_/static/admin.css` 本来就是 dist 任务约定的入口。代价是 apps 页会多下载一些后台样式（约 27KB，没压缩）。错误页没有按状态码换主按钮的目标（比如 429 直接回 `/login`），因为 `BackURL` 是 view model 契约，模板不该自己拼路由。

## 对 M2 页面的影响

`admin.css` 改了两处会作用到 M2 页面的规则，其余全是新类名：

1. 全局 `[hidden] { display: none !important; }`。原因：`.btn` 设置的 `display: inline-flex` 优先级高于浏览器默认的 `[hidden]` 规则，所以 M2 带 `hidden` 的复制按钮在剪贴板不可用时（例如生产环境意外走了 http）其实藏不住，点了也没反应。正常环境下剪贴板可用，按钮本来就会显示，外观不变。
2. `.solo-foot code` 加了 `white-space: nowrap`。M2 的 `solo-foot`（登录页、批准结果页）里没有 `<code>`，所以没有影响。

## AGENTS.md 建议（交给协调者）

替换代码地图里 `internal/server/views/` 一条中关于 `shared.html` 的那句，并补充 apps 域名的页面：

> - `internal/server/views/`：`shared.html` 定义 `meta`、`assets`（参数是静态前缀：admin 用 `"/static"`，apps 域名用 `"/_/static"`，绝对路径，所以 `/_p/<token>/` 下任意深度都能加载）、`head`（参数是页面标题，等于 `meta` + 标题 + `assets "/static"`）、`nav`（参数是当前页 key：`apps` / `previews` / `trash` / `agents` / `events`）、`brand`（后台）、`site-brand`（apps 域名，不带「后台」）、`audit`、`action`（动作码 → 中文）、`visibility`、`code`（验证码加连字符）和 `i-*` 图标。apps 域名的 `root.html`、`preview-expired.html` 不放后台导航，也不能出现表单或密码框（有测试检查）。错误页 `error.html` 用 solo 布局，`data-error-page` 标记要保留。样式全部在 `static/admin.css`，浅色和深色的令牌在 `:root`；全局 `[hidden]` 带 `!important`，因为 `.btn` 的 display 会盖过它。`static/admin.js` 负责 `data-confirm`、`<time data-ts>` 按本地时区显示、`data-copy`、`data-back`（有历史记录时才显示）和账户菜单。CSP 不允许 `style` 属性、`<style>` 和内联 `<script>`，样式只能写进 CSS 文件。操作记录页的审计表要保持字面量 `<table>`，筛选放在表格前面（测试按它切分）。
> - 改了 `views/` 下的任何文件，本地验证前都要重新 build `tinyhost-server`，因为模板和静态文件是 embed 进去的。
