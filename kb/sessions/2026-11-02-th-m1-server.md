## 实现说明

### API 一览

基地址为 apps origin 的 `/_/api/v1`。所有端点只接受 Bearer token，GET 也支持 HEAD；响应为 UTF-8 JSON，API 禁止缓存，不开放 CORS。DTO 在 `internal/api/api.go`，完整字段、请求例子、错误细节在 [JSON 契约](../../docs/json-output.md)。CLI 不应直接序列化 store 的模型。

| 方法 | 路径（基地址之后） | 请求 DTO / body | 响应 DTO（状态） | 业务错误码 |
|---|---|---|---|---|
| GET | `/whoami` | 无 | `WhoamiResult`（200） | unauthorized |
| GET | `/apps` | 无 | `AppsResult`（200） | unauthorized |
| GET | `/apps/{slug}` | 无 | `AppDetail`（200） | app_not_found |
| GET | `/apps/{slug}/versions` | 无 | `VersionsResult`（200） | app_not_found |
| POST | `/apps/{slug}/deploys` | tar.gz + query | `DeployResult`（201） | slug_invalid, slug_taken, app_not_found, bad_bundle, too_large, bad_request |
| POST | `/apps/{slug}/data` | tar.gz + dir/message query | `DeployResult`（201） | app_not_found, overlay_conflict, bad_bundle, too_large |
| DELETE | `/apps/{slug}/data` | dir/message query | `DeployResult`（201） | app_not_found, overlay_conflict, overlay_not_found |
| POST | `/apps/{slug}/promote` | `PromoteRequest`（version 数字） | `PromoteResult`（200） | app_not_found, version_not_found, bad_request |
| DELETE | `/apps/{slug}` | 无 | `DeleteResult`（200） | app_not_found, not_creator |

每个端点还可能返回 unauthorized（401）和 internal_error（500）。错误响应 DTO 为 `api.Error{Error: api.ErrorDetail{Code, Message, Hint, ...}}`。slug_taken 附 created_by/created_at/deleted，overlay_conflict 的嵌套冲突附 existing_dirs。错误路径/HTTP 方法的 404/405 由路由器产生，不保证 JSON。

发布 query 是 `create=1`、`visibility=public|private`、`title`、`message`、`promote=0`。默认更新已有 App，新建默认 private；更新不改变 visibility。返回 DeployResult.app 是 slug 字符串，version 是整数，current_version 可以为 null，data_dir 可以为 null；skipped 是 []string，空时为 []。files/size 只计本次层的托管文件，data rm 为 0。删除返回 trash_days，CLI 应据此提示恢复期限。

查询响应使用 `{apps:[]}`、`{versions:[]}` 包装；详情是 `{app:App,manifest:Manifest,overlays:[]}`。创建者字段都是客户端 ID（预留 owner），不是展示名称。详情 manifest 来自主入口；覆盖目录显示最初推送者/时间，版本列表的 current 标记主入口。whoami 只返回安全的 Client DTO，不包含 token_hash。

### 服务端与存储接法

`Server{Store, Blobs, Config, Now, Logger, OnEvent}.Handler()` 返回完整 Host 路由。`Config.Validate()` 验证 apps/admin 是不同 origin；本期 admin 可省略，配置后所有 admin 请求仍返回 404，未知 Host 返回 421。Config 的 InsecureCookies 已接入，供 M2 使用。

发布时在 SQL 事务外流式解包和写 blob；整个包校验成功后才创建 App/提交版本。data 层文件路径预先加标准化目录前缀。store 已签收接口没有增删改；错误用 errors.Is 映射，创建 slug 的并发唯一性冲突再次查询占用者并返回 slug_taken。

`app.created`、`app.deployed`、`data.pushed`、`data.removed`、`app.promoted`、`app.deleted` 记录到 events，成功落库后调用可选 OnEvent；核心不 import notify。审计写入错误只记录日志，不把已经提交的发布伪装成失败，避免客户端重试重复生成版本。

内容支持 .html 补全、目录 301、自定义 404、覆盖目录不回落、ETag、Range、HEAD 和缓存控制，所有响应加安全头，不发送 Service-Worker-Allowed。URL.Path 已由 net/http 解码，禁止二次解码。相对 spec 的保守处理：含 `..`、隐藏段、反斜杠、NUL 的内容路径直接 404；私有 App 先统一返回 401“需要登录”，包括不存在的版本，以减少私有元数据泄漏。自定义 404 保持 404，不参与 Range/条件 304，缓存为 no-cache。

GC 顺序为清理数据版本 → 七天回收站 → 无引用层 → 重新查询 blob 引用 → 删除超过一小时的无引用 blob。Now 可注入。进程内 lifecycle 读锁覆盖上传/提交，GC 使用写锁，避免 GC 引用快照与新上传交错；两个上传仍可并发。mtime 门槛继续保护刚复用的 blob。`RunGC(ctx)` 每小时执行，context 取消时退出。

### 命令入口

`cmd/tinyhost-server` 使用 stdlib flag 与 register 分发：serve、token create、gc、version。serve 支持 spec 全部参数及对应 `TINYHOST_*` 环境变量；token create/gc 支持 --data-dir 和 TINYHOST_DATA_DIR。TTL 支持 30d、Go duration，默认永不过期；stdout 只输出一次 token 明文，DB 只写哈希。

数据文件固定为 `<data-dir>/tinyhost.db`，文件块由 blob.New 创建。相对目录在入口转为绝对路径，因为 store.Open 的 file URI 对相对路径会出现 invalid uri authority；该问题已由命令层兼容，不改变基础库。serve 使用 JSON slog、请求头超时、空闲超时，收到 SIGINT/SIGTERM 停止定时 GC 并优雅关闭 HTTP。
