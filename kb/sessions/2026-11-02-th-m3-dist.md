## 实现说明

`skill/SKILL.md` 具有 name/description frontmatter，覆盖安装、设备授权、云端 token、目录/manifest、preview/--ttl/--new、路径警告、正式发布、数据目录协作、查询/版本/回滚/删除、JSON/退出码、curl 上传和常见错误。`skill.Render(server)` 同时用于 `/skill.md` 和 CLI；渲染服务器地址和当前构建版本。未配置服务器时 CLI 使用 `https://<your-tinyhost-server>`，不访问网络；配置文件损坏或显式地址非法仍报错。更新了 help/skill golden 与 `docs/json-output.md`，没有新增或改变 API DTO 字段。

`skill/install.sh` 经 `RenderInstall` 填入 shell 安全引用的服务器、版本和 JSON。支持 Linux/macOS × amd64/arm64，curl 优先、wget 回退，sha256sum/shasum 校验，校验后才安装；二进制与 config 使用同目录临时文件再 rename，支持重复安装。macOS 忽略 XDG_CONFIG_HOME，写 `~/Library/Application Support/tinyhost/config.json`；Linux 使用 XDG_CONFIG_HOME 或 `~/.config`，与 Go 一致；配置文件 0600。默认安装到临时 HOME 下的 `~/.local/bin`，可用 TINYHOST_INSTALL_DIR 改。dev 且未配置 dl-dir 时返回只提示开发版本并退出 1 的脚本。

`internal/distribution.Proxy` 负责 `/_/dl/{file}`。只接受安全单段文件名和 checksums.txt 中的名字；checksums 文件本身除外。正式来源为 `https://github.com/<release-repo>/releases/download/v<version>/`，默认 repo 为 reorx/tinyhost；缓存到 `<data-dir>/dl/<version>/`。下载先写临时文件、验 SHA-256 再 rename；缓存命中也重新校验，损坏缓存可重新下载。checksums 解析拒绝危险路径、非法/重复 hash 条目；远端 manifest 上限 1MiB、单包上限 512MiB。`--dl-dir` 使用本地 manifest/包，同样执行白名单和校验，不访问 GitHub；不在名单返回 404，包损坏/上游失败返回 502。GET/HEAD 支持普通文件响应；假 GitHub 测试验证了 repo/tag 路径、缓存复用、损坏重取和本地校验。

新增服务端参数：`--release-repo`、`--dl-dir`、`--ntfy-url`、`--ntfy-token`、`--webhook-url`、`--notify-events`；均沿用现有 `TINYHOST_` 环境变量映射和参数优先规则。通知默认订阅 `device.requested,app.created,app.deployed`，显式列表替换默认订阅。Hub 缓冲 100 条，单 goroutine 顺序发送，队列满丢弃并记日志；各请求超时 10 秒、不重试、不跟随重定向。ntfy 设置 Title/Click/Tags/Priority 和可选 Bearer，中文标题按 RFC 2047 编码；webhook JSON 为 `{event,title,message,url,at}`。失败只记日志，发布结果不变。

核心只依赖事件回调，不 import notify。device/code 在申请落库后新增 `device.requested` 审计，再回调；detail 只有名称、主机名、IP、公开验证码和批准链接，不含秘密 device_code。app.deployed 的 detail 附加 message 以展示版本说明；数据发布仍为 data.pushed，默认不通知。`cmd/tinyhost-server/notify.go` 负责从事件和 store 组织消息、解析 Agent 名称与主入口，接到 Hub。测试同时覆盖 ntfy 头、webhook 内容、实际 device/deploy 接线、队列满与失败日志。

所有 Agent API 路径上的响应（含鉴权错误、路由 404/405）加 `X-Tinyhost-Version`。CLI 使用 `golang.org/x/mod/semver` 比较，在一次命令所有输出结束后向 stderr 提示升级；成功/失败、JSON 输出和退出码不受影响，dev/无法解析的开发版本不提示。CLI 依赖检查确认不引入 server、notify 或 modernc/SQLite。

## 页面清单增量

与 preview 总结的同名节一起交给 th-m3-ui；只增路由/view model，已有表单字段和页面数据未改。

| 页面或资源 | 路由与模板 | 具名 view model / 契约 |
|---|---|---|
| apps 根路径说明 | `GET/HEAD /`；`internal/server/views/root.html` | `RootView` 在 `internal/server/distribution.go`：`AppsURL string`（去末尾斜线的 origin）、`Version string`、`InstallCommand string`（完整安装命令）。HTTP 200；HEAD 无 body；应保留 tinyhost 说明、安装命令、`tinyhost skill` 和 `/skill.md` 链接。没有后台导航或密码输入。 |
| 后台通用错误页 | 下述现有 handler 的错误分支；`internal/server/views/error.html`，无单独新路由 | `ErrorView` 在 `internal/server/errors.go`：`Status int`、`Title string`（当前 http.StatusText）、`Description string`（原错误说明）、`BackURL string`（当前 `/`）。状态码维持原有 400/401/403/404/409/429/500；页面有 `data-error-page` 标记和返回链接，测试依赖标记，重设计时保留。 |
| apps 可信静态资源 | `GET/HEAD /_/static/{file}` | 与 admin `/static/` 共用 embed 的 `views/static/`，无需登录。根页/过期页可用 `/_/static/admin.css`、`/_/static/admin.js`、`/_/static/icon.svg`；这不是用户上传路径。 |

根页 CSP：`default-src 'self'; frame-ancestors 'none'; form-action 'none'`，禁止内联样式/脚本；样式写进 `views/static/`，从同源 `/_/static/` 加载。错误页继承 adminMiddleware 的既有 CSP/no-store，使用 admin `/static/` 资源即可。两个朴素模板目前均无 CSS/脚本，视觉设计留给下一任务；没有改预览页/过期页的现有字段。

会渲染通用错误模板的入口：

- `adminMiddleware`：Origin 403、未登录写操作 401、内部错误 500；未登录 GET/HEAD 继续跳登录。
- `login`：限速 429、坏表单 400、内部错误；密码错误继续渲染原 login.html（401）。
- `adminLogout`、`devicePage`：内部错误；`deviceDecision`：表单/名称/有效期/已处理等 400；`viewAuth`：无效 next 400、内部错误。
- `consoleHome`、`consoleCreateApp`、`consoleApp`、`consoleAppAction`、`consoleTrash`、`consoleTrashAction`、`consoleAgents`、`consoleIssueToken`、`consoleRevokeAgent`、`consoleEvents`、`consolePreviews`、`consoleDeletePreview` 的输入、业务或内部错误。底层经 `consoleForm`、`consoleError`、`consoleFindApp`、`adminInternal` 汇合。

App 详情/操作的不存在响应原先复用了 API 的 JSON 404，现改走 `consoleFindApp` 输出 HTML，同状态和说明；Agent API 的 `findApp` 保持 JSON。apps 的 `/_/auth` 错误不走后台模板。标准 ServeMux/FileServer 生成的未知路由、方法或静态文件错误仍使用标准响应；本任务覆盖业务 handler 的错误出口。

## 验收 6 脚本

脚本：`scripts/accept-install.sh SERVER EXPECTED_VERSION [NEW_WORK_DIR]`。只对可丢弃的测试服务器运行，会创建一条待批准授权。要求 curl、tar、sha256sum 或 shasum；无额外语言依赖。

本机已执行（由 smoke.py 托管服务）：

```sh
mise exec -- make dist VERSION=0.3.0-m3-dist
sh scripts/accept-install.sh http://localhost:3471 0.3.0-m3-dist tmp/tinyhost-v1/work/th-m3-dist/install-accept
```

脚本使用 `env -i` 与全新临时 HOME，不继承 TINYHOST_SERVER/TOKEN/INSTALL_DIR/XDG 配置；运行 `curl .../install.sh | sh`，然后用新装 CLI 检查版本、与 HTTP skill diff、在无服务器/token 环境配置时运行 login。预期输出依次包含：`PASS version=...`、`PASS skill HTTP/CLI identical`、`PASS login created authorization without environment configuration (exit=4)`。证据写到指定目录；目录中的 home 必须不存在，避免意外碰到已有安装。

Linux 容器的运行方式（**未执行**）：在用户选定的 Linux 测试机/CI 上准备同版本服务和 dist，服务 listen `0.0.0.0:3471`、apps-url `http://tinyhost-accept.test:3471`、admin-url `http://admin.tinyhost-accept.test:3471`、`--insecure-cookies --dl-dir <dist绝对路径>`。以下仅供届时执行，不涉及生产；测试宿主机需支持对应架构或已配置仿真：

```sh
# 在该 Linux 测试机的项目根目录，amd64/arm64 各跑一次。
# 每个 evidence 目录必须是全新的；服务端 apps-url 必须与脚本参数完全一致。
mkdir -p tmp/install-linux-amd64 tmp/install-linux-arm64
for arch in amd64 arm64; do
  docker run --rm --platform "linux/$arch" \
    --add-host tinyhost-accept.test:host-gateway \
    -v "$PWD/scripts/accept-install.sh:/accept-install.sh:ro" \
    -v "$PWD/tmp/install-linux-$arch:/evidence" \
    debian:bookworm-slim sh -c \
    'apt-get update && apt-get install -y ca-certificates curl tar coreutils && sh /accept-install.sh http://tinyhost-accept.test:3471 0.3.0-m3-dist /evidence'
done
```

测试完成后在对应 evidence/home 下清除 pending-login.json，关闭测试服务器。不要把这里的 Linux 命令拿到本机运行；本机仅做 macOS 验收。

## AGENTS.md 建议

由协调者合入，本任务未修改或暂存 AGENTS.md。可直接粘贴：

- `skill/`：SKILL.md 与 install.sh 同时 embed；`Render(server)` 填入地址/构建版本，供 HTTP `/skill.md` 和 CLI 共用；`RenderInstall` 对 shell/JSON 做安全引用。安装配置目录必须与 Go 的 os.UserConfigDir 一致：macOS 为 `~/Library/Application Support/tinyhost`，Linux 尊重 XDG_CONFIG_HOME；config.json 为 0600。
- `internal/distribution`：`/_/dl/` 仅提供当前版本 checksums.txt 列出的安全单段文件名；下载/缓存命中/本地 dl-dir 都校验 SHA-256。远端缓存由入口设为 `<data-dir>/dl/<version>/`；临时文件校验通过后才 rename。`scripts/dist.sh` 生成六平台 CLI 包与 checksums，`scripts/accept-install.sh` 使用全新 HOME 验证安装、skill 和 login。
- `internal/notify`：容量 100 的异步队列，默认 device.requested/app.created/app.deployed；ntfy 与 webhook 每请求超时 10 秒、不重试，满队列/发送失败只记日志。事件消息和回调接线在 `cmd/tinyhost-server/notify.go`，核心 server 不 import notify。device.requested detail 不能放秘密 device_code。
- `internal/server/distribution.go`、`errors.go`：apps 根说明页、`/_/static/` 可信资源和后台通用错误页；view model/页面契约见 `kb/sessions/2026-11-02-th-m3-dist.md`「页面清单增量」，UI 设计前先读。admin 业务错误使用 HTML，Agent API 继续 JSON；原状态码不变。
- 所有 Agent API 响应有 X-Tinyhost-Version；CLI 仅对可解析的旧语义版本在 stderr 末尾提示升级，dev 不提示。CLI --json 的 stdout/退出码契约不变。
